# product-review-and-release Specification

## Purpose
Make product review states and release evidence reproducible, traceable and honest about the limits of automated checks and external feedback.

## Requirements

### Requirement: Traceable current asset states
A generated index SHALL contain all 140 stable experiment identities and separate automated evidence, editorial review, scientific check, curriculum check and external feedback states. Six pilots SHALL have explicit review notes; unreviewed items SHALL remain unknown.

#### Scenario: Inspect the asset index
- **WHEN** a maintainer regenerates the index
- **THEN** all catalog routes are covered without inferred student or teacher approval

### Requirement: Browser release gate
Pull requests and deployment builds SHALL use Node24 and a reproducible production server to exercise visible first operation, 2D evidence, 3D or fallback, narrow layouts and persistence. Browser failure SHALL prevent deployment and retain failure evidence.

#### Scenario: A module fails to initialize
- **WHEN** a critical browser interaction fails despite HTTP200 and a successful build
- **THEN** the check fails and deployment cannot proceed

### Requirement: Measured delivery and deferred feedback
Delivery SHALL include reproducible controlled performance measurements before and after changes, affected-area regressions and H01-H12 dispositions. Feedback materials SHALL ask help, interest and one optional comment without inventing responses or requiring external review before implementation acceptance.

#### Scenario: Review delivery evidence
- **WHEN** a maintainer reads the delivery report
- **THEN** measured outcomes, limitations, remaining external feedback and reproduction commands are explicit
