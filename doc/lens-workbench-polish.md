# 透镜标杆打磨：调焦、取景与证据

日期：2026-10-16。对应产品打磨规划优先级 1；后续重心 A/B 对照和莫比乌斯逐段剪切尚待各自开发与试用。

## 学生怎样开始

进入 `/labs/lens/` 后，先点“开始第一次调焦”。装置准备好 f=10 cm、u=30 cm、屏距 8 cm；只移动光屏，把模糊的 F 调清晰。成功由手动操作后的模型清晰度判定，标准演示不算完成。也可以直接拖装置，或点“自由探索”。

预测、五种情景、标准演示和视角收在“更多探索”中，仍可随时展开。模型、公式、三维/二维切换、键盘微调和无脚本静态说明继续可用。

手机调参数时，控制区顶部的“光屏取景窗”跟随滚动，显示与主观察窗相同的图案、模糊程度、状态和距离。虚像时不会显示清晰的屏上 F；仍需从透镜另一侧观察。

## 怎样留下和比较证据

“记下这一刻”最多保存六组条件，保存在当前浏览器，不上传，不跨设备同步。刷新后不会悄悄改变装置；点表格中的“恢复”明确恢复某组，光路和读数重新计算，正在进行的演示停止。

最近两组会列出固定条件与改变变量。建议保留 f=10、u=30、屏距=15 的清晰像，再改 u=15、屏距=30，比较像距变化。重新调焦所需的屏距调整会明确说明。若同时改变焦距，提示先固定焦距；若两组尚未对焦，不把它们当作清晰实像对照。

“清空记录”和“重新探索并清空记录”都会删除本机记录。存储被禁用时仍可实验并保留页面内记录，页面会明确提示。无效记录不会注入表格或送入模型。

## 挑战反馈

实像任务分别诊断：虚像不可投屏、焦点处光线平行、像距超过 100 cm 光屏行程、像大小不符，以及大小正确但未对焦。每次给出与当前条件对应的下一步，而非同时堆叠多个建议。

## 自动验收

- `npm test`：55 项模型与逻辑测试通过，覆盖记录版本/范围/步长、损坏数据、控制变量比较和诊断分支。
- `npm run build`：Astro 类型与模板检查 0 错误、0 警告；19 页构建成功。Vite 保留现有 Three.js 大包体积提示。
- `npm run test:browser:lens-workbench`：6 项通过，覆盖首次手动调焦、演示不代做、刷新恢复、取消旧演示、清空本机记录、状态诊断、320/390px 同屏视窗、损坏和禁用存储。
- `npm run test:browser:lens`：通过，覆盖既有透镜与路线回归。
- `npm run test:browser:spatial`、`npm run test:browser:observation`：均通过，检查折叠工具与手机新取景窗没有破坏三维操作及其他实验观察条。

浏览器检查命令支持 `BROWSER_CHECK_URL` 指向现有服务。新 Playwright 检查也可自行启动开发服务。截图输出在忽略版本管理的 `test-results/`。

## 真实试用仍需完成

邀请 3–5 位目标年龄体验者，不提前教操作，记录：首次独立调焦耗时、停顿与求助、误操作、调参时寻找画面的次数、能否根据提示修正、能否用两组证据解释变化。最后给一个新物距，先预测再验证。先依据观察确定后续目标值；自动测试和小样本均不能证明教学效果。
