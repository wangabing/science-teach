# 现有实验产品打磨与同类产品对标分析

日期：2026-10-16。

本文整理现有 12 个实验的产品打磨方向，作为后续讨论和规划依据。文中的功能建议尚未实施，也不代表已经确认的开发范围。

## 1. 核心判断

下一轮最有价值的方向，是把已有实验打磨成“容易开始、能自己发现规律、做完能解释”的完整体验。

现有产品已经具备直接操作、标准演示、实时数据、公式联动，以及部分实验的预测、对照和挑战。主要改进空间在于这些能力如何组织，以及各实验体验深度的不均衡。

建议优先关注：

1. 首次操作是否明确、轻松。
2. 手机操作时是否能同时看见现象。
3. 失败反馈是否指向当前问题。
4. 是否能保留和比较证据。
5. 挑战完成后是否能验证理解。
6. 发现是否能保存，实验之间是否有连贯路线。

## 2. 分析依据与对标范围

本站分析基于当前代码、验收文档与已有截图，包括实验页面、交互逻辑、观察记录、短探索路线，以及近期共同体验审阅。本轮未重新执行完整浏览器验收，也尚无青少年参与者的试用结果。

本次访问外部网站时联网失败。竞品比较参考这些代表产品的成熟设计方法，不是对其最新版本的逐页实测，也不构成完整的竞品排名。

| 参考产品 | 值得借鉴的能力 | 对本站的启发 |
|---|---|---|
| [PhET](https://phet.colorado.edu/zh_CN/) | 用清晰装置和必要控件支持探究 | 初次进入突出一个操作，测量与高级参数逐步展开 |
| [Mathigon / Polypad](https://mathigon.org/polypad) | 对象直接操作、即时反馈、自由构造 | 几何和建造实验强化“我在操作对象”的感觉 |
| [Nicky Case](https://ncase.me/) | 短解释与小操作交替推进 | 把长篇原理拆到学生刚刚遇见问题的位置 |
| [Ray Optics](https://phydemo.app/ray-optics/) | 案例进入工具，工具支持继续探索 | 从拍照、投影、放大镜任务进入，并支持保存和重现设计 |

这些产品分别擅长模拟、工具和互动解释，应选择适合本站的做法，不要求所有实验套用同一种模板。

## 3. 六项改进方向

### 3.1 明确第一件事，降低首次操作负担

透镜页在主要装置之前，已经出现预测、两个演示、五种情景和多个视角。它们各有用途，但第一次进入的学生需要先判断“我该点哪个”。

建议每个实验提供一个明确的首次动作：

| 实验 | 首次动作示例 |
|---|---|
| 透镜 | 先移动光屏，让 F 变清楚 |
| 单摆 | 拉开摆球，松手，观察一次能量交换 |
| 月相 | 移动月球，看右侧月亮哪里发生变化 |
| 桥梁 | 先给这个四边形加一根斜撑 |

完成首次动作后，再引出下一层问题。保留自由探索入口，不强制所有学生遵循步骤。

### 3.2 为手机设计更紧凑的操作台

近期加入的实时观察条改善了读数反馈，但现有手机截图显示：调整透镜参数时，仍然看不到光路和光屏，需要读数或返回画面。

建议先在一个实验试做紧凑模式：上方保留装置或关键观察窗，下方只显示当前任务需要的参数，其余工具收起。

各实验保留的视觉证据应有所不同：

- 透镜：光屏小窗与清晰度变化。
- 月相：地球所见的天空月面。
- 重心：重力线落点与支撑面。

目标是让学生拖动时就能看见现象；是否采用固定区域、局部小窗或其他布局，需要结合实际设备和试用结果确定。

### 3.3 让失败反馈指出具体问题

现有挑战已经提供反馈，但部分反馈主要依赖文字，或一次给出多条建议。

例如桥梁不可求解时，目前提示加斜撑或检查孤立节点。可以进一步尝试：

- 有孤立节点时，直接标出对应节点。
- 能可靠识别局部机构时，展示其可能的移动方向。
- 先给观察提示，再按需提供更具体的帮助。

透镜应区分不同失败原因，例如“像的大小符合要求，但光屏没有对焦”和“当前形成虚像，光屏接不到”。

反馈应与当前装置状态对应。具体诊断必须有模型依据，不能仅凭统一文案推断故障原因。

### 3.4 从显示证据走向比较证据

实时读数与公式已经比较丰富，但学生仍需要记住上一个状态，才能判断变化。

建议优先提供“保留这组，再试另一组”的简单对照：

| 实验 | 最有价值的对照 |
|---|---|
| 重心 | 同样质量、同样倾角，只改变配重高度 |
| 月相 | 同样满月位置，只改变交点方向 |
| 透镜 | 同样焦距，比较三组物距与像距 |
| 桥梁 | 同样载荷，比较加斜撑前后的结构 |
| 三体 | 保持共同条件，比较相同时刻的分离量 |

透镜已有最多六组的页面内记录，单摆已有参考摆，可以在现有能力上继续打磨。对照中应明确固定条件与改变变量，避免把多变量变化误当作单一因素的证据。

### 3.5 挑战完成后，继续验证理解

部分挑战以数值或状态达标为终点。学生可能通过反复试滑块完成，却仍然说不出原因。

建议成功后增加一个简短的迁移问题：

| 实验 | 迁移问题示例 |
|---|---|
| 重心 | 所有质量同时加倍，临界角会变吗？ |
| 齿轮 | 只换中间轮，输出速度会变吗？ |
| 月相 | 把月球移出地影，满月还存在吗？ |

先预测，再操作验证，用证据解释结果。这样可以进一步辨别偶然达标与掌握关系，也为第二次探索提供目的。

### 3.6 保存发现，改善实验之间的衔接

当前透镜记录只保留在当前页面；本次代码检索未发现全站的持久保存或参数分享机制。

可考虑以下轻量能力：

- 本机保存观察记录。
- 保存一组实验条件并恢复。
- 用链接分享实验参数。
- 导出包含条件、证据和个人解释的发现卡。

现有短探索路线也值得重审。例如“从一束光，到一幅像”接到单摆，目前依靠控制变量和测量方法衔接，主题连续性偏弱。

建议明确区分主题路线与方法路线，并说明为什么接下来要进入另一个实验。路线应帮助学生建立联系，而不只是提供下一页入口。

## 4. 下一轮建议优先级

建议先集中打磨三个代表实验，再根据试用结果决定哪些做法推广到其他实验。

| 顺序 | 实验 | 本轮重点 | 代表的体验类型 |
|---|---|---|---|
| 1 | 透镜成像 | 首次调焦、手机观察窗、按失败原因提示、记录恢复 | 仪器操作 |
| 2 | 重心与稳定 | 固定条件的 A/B 对照、挑战后的迁移验证 | 控制变量 |
| 3 | 莫比乌斯带 | 逐段剪切过程、剪后继续追踪，使连接关系可验证 | 空间理解 |

首选是把透镜做成标杆：从进入页面，到独立调出清晰的像，再到用两组记录解释规律，形成顺畅、可验证的完整过程。

## 5. 验收与用户试用建议

在现有模型、交互和浏览器检查之外，增加真实使用观察。

建议邀请 3–5 位目标年龄体验者，记录：

- 能否独立完成第一次操作，以及耗时。
- 在哪里停顿、误操作或需要求助。
- 调参数时需要多少次往返寻找画面。
- 是否能理解失败原因并自行修正。
- 能否用记录和读数解释结果。
- 面对一个新条件，能否先预测再验证。

小样本用于发现可用性与理解障碍，不据此宣称已经证明教学效果。具体目标值应在首轮观察后确定。
